# ghx · GitHub 访问加速工具

ghx 是一个运行在自己电脑上的小工具，用来改善访问 GitHub 时的体验。

它只有一个窗口和一个按钮，启动之后不需要再做其它操作。整个工具完全在本机工作，不借助任何第三方的加速服务、镜像站点或公共转发服务，也不把使用者的网络流量交给别人。

---

## 它面向的问题

访问 GitHub 时常见的不顺有三种：

- 页面打不开，或者一直停在加载状态；
- 页面能打开，但速度很慢，时快时慢；
- 下载代码或文件的过程中卡住，甚至中断。

这三种表现的背后是同一件事：电脑拿到的 GitHub 地址不合适。它可能是错的，可能是绕了远路的，也可能一时能用、一时不能用。

## 基本思路

工具做的事情可以概括为三步。

**第一步，确认 GitHub 的真实地址。** 它同时向几个公开的域名查询服务询问，把各家给出的结果汇总起来，不单独听信任何一家。

**第二步，在本机逐个试用。** 对每一个候选地址，工具会自己发起一次真实连接，测量从这台电脑出发需要多久才能连上，并检查对方是否真的在提供所要的服务。响应过慢的、身份对不上的、只回一句空话而不提供内容的地址，都会在这一步被排除。

**第三步，选定并持续维护。** 挑出当下最合适的一个地址，之后的访问就从本机直接连到它；其余的按顺序留作备用，一旦当前地址失效，下一条连接会自动换用下一个。运行期间，工具会定期重新确认，也会在连接失败时重新挑选，不需要使用者手动重来。

在整条链路上，工具只决定"走哪个地址"，不改变访问的内容，也不查看传输的数据。数据在浏览器（或命令行工具）与 GitHub 之间加密传输，工具只负责把它们原样送过去。

## 使用方式

1. 电脑上需要有 Python 3.10 或更新的版本，不需要安装其它组件。
2. 在项目目录执行 `python main.py`。
3. 点击窗口中央的圆形按钮。按钮先显示"启动中"，完成后变为绿色，此时访问 GitHub 已处于加速状态。
4. 再次点击同一个按钮即可停止，电脑的设置随之恢复原样。

按钮下方显示两个累计数字：经过工具转发的请求数，以及上传与下载的合计流量。这些数字跨次使用累加，只记录在本机。

启动时，工具会先处理打开页面和取用代码会立刻用到的那几个服务，通常几秒钟即可开始使用；其余服务的准备工作在后台继续，不占用等待时间。

## 适用范围

- 只对 GitHub 及其相关服务生效。其它网站完全不经过这个工具，上网方式与原来一致。
- 自动调整电脑设置这一步目前只在 Windows 上实现。其它系统可以打开界面，但不会自动接管设置。
- 对使用 SSH 方式的代码仓库不起作用，这类连接不经过工具的通道，建议改用 HTTPS 方式访问。
- 少数网络会按服务名称整体拦截某些地址，这种情况下换哪个地址都没有效果。工具会识别出这一类情况，记录下来并在一段时间内跳过，不再反复尝试。

## 对原有设置的处理

启动之前，工具会完整记下电脑上原有的网络设置，包括公司或校园网常用的自动配置方式；停止时按原样写回，而不是简单关闭。

如果程序被强行结束，设置可能停留在工具留下的状态，导致浏览器无法上网。下次启动时工具会发现这一点并自动还原，同时给出提示。

工具不修改系统的本地映射文件，也不需要管理员权限。

## 数据与隐私

- 只在本机内部收发数据，不接受来自局域网其它设备的连接。
- 除域名查询与 GitHub 自身之外，不与任何第三方通信。
- 不统计、不上报使用情况。本机只保存少量记录文件，用来记住上次挑选的地址与累计用量。

## 文件说明

所有代码平铺在项目根目录，没有子目录，也没有第三方依赖。

| 文件 | 作用 |
| --- | --- |
| `main.py` | 程序入口与窗口界面：一个圆形按钮、一组累计用量，以及启动时的分阶段准备 |
| `config.py` | 常量、状态目录、内置的服务清单，以及启动时优先处理的服务 |
| `net.py` | 地址的获取与挑选：查询、试用、排序，以及查询全部失败时的备用方案 |
| `store.py` | 本机文件读写：挑选结果的记录与累计用量 |
| `proxy.py` | 本机的转发通道与分流规则 |
| `syscfg.py` | 接管与还原电脑的网络设置和代码工具的设置 |

运行后会在用户目录下生成一个隐藏文件夹，存放上述记录文件。删除它不影响使用，只是会重新积累。

## 已知边界

| 情况 | 说明 |
| --- | --- |
| 个别服务无法解决 | 某些网络按服务名称整体拦截，换地址无效。工具会识别并短暂跳过，不再重试。 |
| SSH 方式不受影响 | 通过 SSH 访问仓库不经过本工具的通道。 |
| 仅 Windows 可一键完成 | 自动调整设置这一步依赖 Windows 的系统能力。 |
| 部分服务首次访问略慢 | 启动时只准备常用的几个服务，其余的在后台补；因此刚启动时访问较少用到的服务，第一次会稍慢。 |
| 地址会变化 | GitHub 使用的地址会变动，工具的记录有效期有限，过期后自动重新挑选。 |
| 提升有限 | 它改善的是"从哪个地址连过去"，不能突破网络本身的速度上限，也不能绕过访问限制。 |

## 定位

ghx 只做一件事：在自己电脑上为 GitHub 找到当下最合适的连接地址，并让这件事做得安静、可回退、不干扰其它上网行为。它不改变访问内容，也不替使用者决定能看到什么。
